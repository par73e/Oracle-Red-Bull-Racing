# 每个滑块逐档 CFD · 2026-11-12

Sir 确认逐项算全，多个参数同时偏离基准时接受近似。基准：来流 180 km/h、对地车速 180 km/h、DRS 关闭、转向 0°。地面速度等于对地车速，四轮角速度为对地车速除以各轮半径。所有结果属于展示模型代理的探索性稳态 RANS，不是经验证的赛车性能。

|单独变化项|范围|步长|档位数|
|---|---|---|---:|
|相对来流|0–350 km/h|5 km/h|71|
|对地车速|0–350 km/h|5 km/h|71|
|DRS 开度|0–100%|1%|101|
|前轮转向控制|-18–18°|1°|37|

四条轴共用一个基准，故每车 277 个唯一工况、两车 554 个。复用每车 7 个已计算节点（base、open、left、right、road-stop、road-slow、still-air）；其余 540 个依次计算。此前 low/high 同速节点和 road-fast 等仍保留作回退依据，不冒充逐项新算例。转向是网页机构控制值，各轮真实转角仍由机构解算；这里的纵向轮周速度匹配不代表真实转弯无侧滑运动学。

## 执行与恢复

```sh
cfd/.venv/bin/python -u cfd/library/sweep/run.py
```

队列先等待本轮 8 个 rolling 种子完成，再在两个车型之间交替、逐工况串行执行；每例最多 4 个求解进程。只修改项目专用 `aero-cfd` 本地 VM 的新算例。未完成目录留在 `cfd/library/cases/<car>-sweep-<key>`，不覆盖旧算例，不删除文件。剩余空间低于 30 GiB、网格失败或求解发散时停止并记录错误，不跳过后宣称完成。重新运行会复用已完成记录和网格；中断求解按原脚本重新分解初始场再求解，不把部分迭代当作完成。

速度变化复用该车型原基准网格；DRS 和转向中间档位从真实 GLB 的机构姿态导出表面，单独封闭体素代理并重新划网格。没有启动 Blender。每例 650 步，逐例记录网格、代理哈希、残差、异常取样、原始最高速度与发布数据哈希。

进度：`cfd/library/reports/sweep-status-2026-11-12.json`。运行日志：`/private/tmp/aero-sweep-run-2026-11-12.log`。每车网页清单：`web/public/flow/<car>/sweep/manifest.json`。清单原子更新，公开已完成数量和计划数量；全量完成后自动执行 `finalize.py`，检查全部节点、边界与哈希、流线碰撞、底盘/侧箱回归并重新构建网页。失败会将队列状态标为 failed，不能视为任务完成。

## 网页数据与组合近似

页面速度步长为 5 km/h。单独变化一个控制项，且对应计算已发布时，直接使用该档位场；DRS 动画中的非整数开度采用相邻已计算节点插值。未完成节点暂用 rolling 稀疏代理，界面明确提示“尚在计算，暂用近似”。页面每 10 秒读取覆盖进度，按需加载实际需要的流场，最多保留 16 个逐档场以控制内存。开发服务器通过专门的只读 `/flow/` 文件中间件读取新增文件，避免 OrbStack 文件写入未触发 macOS 文件监视而遗漏数据；本轮源站为 http://127.0.0.1:5173/。

同时改变多个滑块时使用以基准为中心的加性差分：`F_air(U) + F_ground(G) - F_base + (U/50)*(F_DRS(d)-F_base + F_steer(s)-F_base)`，m/s 为内部单位。为使所有速度趋零时连续归零，再乘 `min(1,(U+G)/50)`；该因子在任一速度为 50 m/s 的各条计算轴上均为 1。此组合不是新求解，不保证守恒或高阶耦合；不以所有单轴档位完成冒充所有参数组合完成。

底盘/侧箱的加密场仍只有旧的 180 km/h 基准，其他工况采用原加密基线与粗场差分，不是新的局部加密 CFD。轮胎仍为旋转壁面、无边界层网格的体素代理，不包含胎纹、受载形变及瞬态轮辐细节；转向近壁准确性和高速不可压误差仍有限制。末步有限值或固定 650 次迭代不代表严格收敛，质量汇总不用于真实赛车气动判断。
