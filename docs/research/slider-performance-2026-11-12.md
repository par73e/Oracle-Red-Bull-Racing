# 滑块卡顿排查与修复 · 2026-11-12

拖动不会触发 OpenFOAM。先前网页将速度场混合、整车流线追踪、底盘加密场差分、侧箱/悬挂取样以及三角面碰撞检查都放在主线程的渲染循环中；输入变化会重新生成三组线。后台本地 CFD 同时用四个 solver rank，占约四核，是资源竞争因素，但网页同步长任务是直接阻塞界面的路径。

同一 RB19 基准场景实测同步工作约 146.9 ms（整车 58.2、底盘 38.2、侧箱 50.5 ms）。浏览器渲染线程在这段时间内无法处理后续输入与绘制。新实现通过一个模块 Worker 执行同样的场混合和流线/碰撞代码，模型几何仅在初始化时传入；每次任务仅同步机构矩阵、发生变形的 fairing 位置及缺少的场数据。三组线的 typed array 转移回主线程显示，不在主线程重算。一次只允许一个工作任务，期间只保留最新控制状态；车型/数据切换时销毁旧 worker，过期姿态的结果不会覆盖新姿态。

主线程提交任务实测约 0.3–0.5 ms。后台 CFD 保持运行时，24 次连续速度变化的约 2 秒测试记录 59 帧、帧间隔中位约 33.3 ms、P95 50 ms、无 50 ms 以上 long task；隐藏气流的同条件测试也为 59 帧，说明本次测试中流线工作不再产生额外的界面长任务。此数据来自本机 ego lite，不代表跨设备 60 FPS 保证。Worker 本身仍需约 150–260 ms 完成一组计算，流线异步跟随；车轮、尾翼、控件和模型渲染不再等待这组计算。

`npm run validate:worker` 在两个车型分别核对固定来流/低对地速度、转向+DRS 组合、零来流行驶：Worker 与原同步算法的整车/底盘/侧箱线段数相同，坐标差小于 1e-5 m，包含动态 fairing 的更新与完整模型碰撞。实际 CFD 工况、逐档队列、插值规则和全密度流线不因性能修复而删减。源代码中用于同算法计时的开发诊断函数在生产构建被剔除。
