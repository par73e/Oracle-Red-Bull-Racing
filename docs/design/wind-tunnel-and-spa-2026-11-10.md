# 真实来流风洞与斯帕场景设计

日期：2026-11-10。此文保留最初设计时的状态与建议，属于历史方案。当前实现、已求解工况及限制以 `cfd/library/README.md` 和 `web/README.md` 为准；未完成的工程验证不能因页面实现而视为已完成。

Sir 已确认“艾尔罗格”指斯帕 Eau Rouge／Raidillon，要求真实物理来流，并允许弯道远景模糊。方案扩展现有赛车观察页，保留其版式、车辆操作和近景能力，不重做网站身份。

## 1. 物理计算与图像渲染

Blender 自带流体域、气体／烟雾、流入／流出和初始速度设置，可以让示踪烟雾绕过障碍物。它适合搭建环境和做流动预览。本项目要获得有依据的压力、近壁面流动、尾流与升阻力，采用专用 CFD 求解及验证；不能把 Wind 力场、噪声粒子或手绘绕流曲线当成汽车气动计算结果。

建议流程：

1. 从当前制作副本派生独立的气动计算几何，保留原展示资产。
2. 审计单位、车长／宽／高、离地间隙、法向、孔洞、自交、内外面、轮地接触和封闭边界。贴花、双面装饰片、小紧固件不直接进入体网格；前翼、底板、扩散器、轮胎与尾翼等关键表面保留。
3. 用固定版本的 OpenFOAM 建立算例并验证。不要混用不同发行分支的字典、命令或教程。
4. 导出有物理单位的速度场、压力／Cp、流线与切片；用 Blender 制作离线画面，用网页加载轻量化结果。
5. 每份结果携带车型、几何摘要、DRS、速度、转向／偏航、车高、网格、湍流模型及收敛报告。网页只显示匹配当前工况的数据。

现有底板与机构含展示近似。即使数值求解收敛，结果也只能代表这份模型，不能直接当成真实 RB19／RB16B 的车队气动数据。本机 PATH 只读检查发现 Docker 客户端，未发现 simpleFoam、foamRun 或 pvpython；没有验证 Docker 服务、安装求解器或估计耗时。

## 2. 来流与边界条件

以车辆固定的参考系工作。当前网页是 glTF Y 向上、+Z 指向车头：上游位于车头前方 +Z，空气从 +Z 吹向 -Z；不能因为相机转动而改变来流方向。Blender 对应 Z 向上、车头朝 -Y，来流方向为 +Y。

| 部分 | 初始设计 |
| --- | --- |
| 首个工况 | RB19，180 km/h = 50 m/s，DRS 关闭，转向 0、偏航 0；为建议基线，尚未求解 |
| 空气 | 记录温度、压力、密度和黏度；按基线工况评估不可压缩近似适用性 |
| 入口 | 指定均匀平均速度与有记录的湍流强度／长度尺度，不靠烟雾源速度替代整个入口边界 |
| 出口 | 压力参考与合适的回流处理，位置需避开主要尾流；检查质量流量守恒 |
| 车身 | 固定无滑移壁面；工程简化内容随算例记录 |
| 地面／滚带 | 在车辆参考系中与来流同向运动，速度大小为 U |
| 车轮 | 绕各自真实轮轴施加旋转壁面条件，按滚动方向取角速度，满足轮地接触处速度与地面一致；需要轮辐真实运动时另用滑移／动态网格 |
| 计算域 | 以车长 L 为尺度，初始自由来流域可从鼻尖前约 3L、车尾后约 6L、两侧各约 2L、上方约 3L 起步，再做域大小敏感性检查；这些是初始设计值，非已验证尺寸 |
| 湍流 | 初轮稳态 RANS k-omega SST；检查近壁处理与 y+ 是否相容。需要时再做非定常尾流，不默认以 LES 开始 |

必须区分两种算例：自由来流域外边界与有实体试验段壁面的封闭风洞。后者要真实建入壁面、滚带、支撑及阻塞效应，侧壁不能随意设成自由滑移。网页可采用原创的全尺寸风洞展示环境，但在没有该风洞几何算例时，不声称展示房间的壁面效应已经求解，也不冒充红牛真实设施。

首轮先求 RB19 关闭 DRS 的一个基线，再对比同速开启 DRS，之后处理 RB16B。速度变化不只意味着把同一批粒子播放得更快；车高、转向与偏航变化也不自动获得新物理结果。

## 3. 网页场景

访客模式为 Experience：赛车和流动现象是主体，场景选择与参数只占小范围。保留当前无环境的验收视图，新增以下三个场景。

### A. 风洞试验段

原创的功能性风洞，不复制未经证实的车队设施。车头对准收缩段与整流入口，车尾对准扩散／排气方向。来流入口、示踪烟线、车辆、移动滚带、出口有可读的先后关系。

- 近景：真实几何的滚带、地面边界、玻璃观察窗框、少量测量支架；不让管道或灯带遮住车轮、底板与尾翼。
- 中景：试验段壁面、收缩入口、扩散出口；整流网放在合理的上游位置，不贴在鼻锥前。
- 光照：宽面顶灯与侧灯，玻璃、混凝土和金属反射服从同一环境；碳纤维近景可读。
- 气流：默认清晰车体；按需打开单组烟线、速度切片或压力表面，避免所有颜色和粒子同时叠加。
- 控制：来流速度独立于原“车轮自转”演示输入；有效算例中按来流同步滚带和轮速。切换 DRS、偏航等条件后匹配结果，未计算则显示“该工况尚无流场结果”，不沿用旧压力图。

### B. Eau Rouge 谷底入弯

主视角选在谷底附近，让车辆沿真实驾驶方向进入左转并朝 Raidillon 上坡。画面必须读出下坡结束、压缩区与随后右转上坡的空间关系。

- 近景：有厚度的沥青路面、路肩、草地接边、护栏与接地阴影；道路不能是赛车下方的一块水平平面。
- 中景：上坡道路及缓冲区真实转向和遮挡，不能用模糊平面道路冒充上坡。
- 远景：阿登林地、对应位置的看台与建筑。只在取证后确定建筑摆放和朝向，不随机拼装“欧洲赛道”元素。
- 车辆：车身朝向与路面切线一致，四轮落在局部路面；需要呈现谷底载荷时应加入悬架／车辆动力学。当前模型没有受载悬架，因此首版只能表示几何姿态，不能宣称真实压缩载荷。

### C. Raidillon 上坡／坡顶

第二个赛道视角使用同一地形与年代数据，展示右转上坡、坡顶左转与遮挡关系，增加地形识别度，而非只换天空或背景颜色。坡顶遮挡和地平线正确后再做轻微远景虚化。

- 近景道路坡度与车体俯仰对应；接地位置通过各轮接触点和局部路面计算，不能将整车绕视觉中心硬倾斜后任车轮悬空。
- 不将平直风洞算例直接标为组合弯真实流场。真实过弯还涉及转弯半径、偏航、速度、高程曲率、车高／俯仰及轮载；这些需要独立车辆动力学和气动工况。
- 静态展示与跟车镜头使用不同模糊规则：静态视图只做景深；跟车镜头才使用与速度、曝光和方向一致的环境运动模糊。暂停速度感时不保留高速拖影。

## 4. 斯帕真实性约束

已核实，赛道官方 2022 年说明新增了黑黄红缓冲区涂装，并说明红黄路肩及扩建缓冲区。2021 与 2023 因此不能共用全部环境细节。

建议环境绑定车型年代：RB16B 使用 2021 参考，RB19 使用 2023 参考。此为本方案建议，用户尚未单独指定场景年代。尚未获得可测量的赛道三维高程数据，不填造精确坡度、弯道半径、路宽或车辆载荷。

制作前收集对应年份的官方赛道图、实拍／车载多视角和有许可的环境素材；对齐轨迹、地形、道路边界和建筑后再上材质。需要可自由移动相机时，采用真实 3D 近中景，远景才可使用全景图或简化几何。单张照片仅可用于受限固定视点，不能在任意绕车视角下当作完整环境。

背景模糊根据深度和对焦距离处理：赛车主体与近处路面保持清晰，远处林线和看台柔化；不对整个画布施加 CSS blur。路肩配色、地形轮廓、光照方向和车窗／车身反射仍保持可辨的一致性。是否加入雨天留待后续；首版建议阴天干地，避免把湿地反射与干胎高速驾驶混为一体。

## 5. 数据与交互契约

展示用 GLB 与计算用封闭几何分开。流场导出保留 SI 单位、坐标系、局部／世界变换和裁剪范围；网页流线从实际速度场积分，沿线动画按采样速度推进。稳态算例的流线动画只表达稳态场中的运动，不称为已经求得的瞬态湍流。

结果元数据至少包含 `car`、`geometryHash`、`sceneDomain`、`speedMps`、`drs`、`steerDeg`、`yawDeg`、`rideHeight`、`solver`、`meshId`、`convergence`、`fieldFiles` 和 `validationStatus`。插值结果标明范围，超出范围不给出虚构压力、Cd 或下压力。升阻力系数必须说明参考面积、方向、密度和参考速度。

界面保留车型、观察角度和机械控制。新增紧凑场景选择“风洞／Eau Rouge／Raidillon”和必要的工况选择；场景加载中、资产失败、低性能、无匹配流场和暂停状态均有明确反馈。窄屏降低环境细节与后处理成本，保留车辆近景质量；优先停用远景运动模糊，不能牺牲控制可用性。

## 6. 实施与验收顺序

1. 几何审计及斯帕参考资料表，明确可计算边界与尚缺数据。
2. 风洞与两处赛道视角的灰模。先验收方向、地形、轮地接触和相机，再加材质与模糊。
3. 建立一个可复现 CFD 基线。网格质量、质量守恒、残差与力监控共同验收；至少做网格／域敏感性研究，不用“跑完”代替收敛。
4. 加入有依据的流线／压力可视化及网页交互；比较 DRS 条件时使用实际求解的两份结果。
5. 渲染与浏览器回归：两车、三个场景、桌面／窄屏、场景切换、DRS、转向、轮速、加载失败和无流场状态。

Blender 严格单进程，逐文件保存、退出并确认结束后处理下一项。不启动并行渲染、不覆盖原始资产；在知道网格规模和本机资源之前不承诺运行时长，不自动租用云算力。
